What is composition?
"Has-a" relationship
Composition vs Inheritance
When to use composition
Examples
    - Composition is a design principle where a class is composed of one or more objects of other classes, establishing a "has-a" relationship to build complex behaviors from simpler parts.

3. Magic (Dunder) Methods
Study:
__str__
__repr__
__len__
__eq__
__lt__
Learn why Python automatically calls them.
    - Magic or dunder methods are special built-in Python methods with double underscores that let you define how custom objects behave during standard operations like printing, comparing, or calculating length.

4. SOLID Principles (Introduction)
Understand only:
Single Responsibility Principle
Open/Closed Principle
    - The Single Responsibility Principle states a class should have only one reason to change, while the Open/Closed Principle means software entities should be open for extension but closed for modification.

5. Composition vs Inheritance
Explain:
When should you inherit?
When should you compose objects instead?
    - You should use inheritance when a child class is a specialized version of a parent class, whereas you should use composition when a class needs to use the functionality of another object without establishing a rigid genetic relationship.
